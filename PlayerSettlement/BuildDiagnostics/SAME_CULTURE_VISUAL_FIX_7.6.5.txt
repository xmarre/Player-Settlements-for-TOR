Player Settlements 7.6.5 - strict TOR culture visual recovery
================================================================

Symptom
-------
A non-Asrai settlement could display the Wood Elf/Asrai campaign-map model.

Trigger
-------
A TOR template visual failed or an automatic retry was requested while the
available-model list contained templates from more than one culture.

Contributing factors
--------------------
- Several TOR 1.16 template records pointed at legacy or generic prefab IDs.
- The old expanded TOR Prefabs directory cannot be loaded safely in this build.
- The 7.6.4 retry called UpdateSettlementVisualEntity again, which advanced the
  global model index before attempting recovery.

Root cause
----------
Recovery was scoped to the full model list rather than the selected culture.
The first viable entry after a failure could therefore be Battania/Asrai, which
is the Wood Elf visual set.

Violated invariant
------------------
A visual failure may change the model variant. It may never change the culture
chosen for the settlement.

Patch
-----
- TOR preview visuals are copied from an existing visible campaign settlement
  with the exact same Culture.StringId and settlement type.
- Town/castle recovery may use the other fortification type only when that TOR
  culture has no exact-type source. It never crosses culture boundaries.
- Variant numbers deterministically select among existing same-culture sources.
- Both automatic cross-list retry paths are disabled.
- Created TOR settlements use the same strict culture-copy path when their map
  entity is instantiated after construction or save loading.
- Player-created settlements are never used as recovery sources, preventing a
  previously incorrect model from propagating.
- TOR template prefab_id overrides were removed. A failed exact-culture copy now
  cancels placement rather than silently loading a generic or Asrai visual.
- Native and unrelated third-party template packs retain their original prefab
  behavior; the helper is active only for identifiers containing _ToR.

Runtime uncertainty
-------------------
The binary and XML paths were validated statically. Campaign-map rendering still
requires an in-game Bannerlord 1.3.15 / TOR WiTM 1.16 test.
